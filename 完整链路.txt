六、关键技术决策
决策	选型	原因
Agent 编排	LangGraph StateGraph	6 节点有向无环图，条件路由，状态 TypedDict 贯穿
向量检索	Milvus 2.4 Standalone	4 个 Collection 分维度存储，IP 内积度量
LLM 调用	OpenAI 兼容接口	单例 ChatOpenAI，支持任意 base_url 切换
前端框架	Vue3 + Element Plus + Pinia	SPA，Axios 直连后端
异步通信	直连 HTTP（方案文档写 RabbitMQ，代码实际未用）	当前实现 backend → agent 是同步 HTTP
配置继承	三级模型 (global → canteen → stall)	SystemConfig 表 scope + scope_id 实现
七、完整链路一句话
用户上传评价 CSV → ETL 解析入库 → 关键词预处理(情感/维度/风险) → Agent 6节点流水线(清洗→消歧→知识检索→冲突检测→置信度评估→整改单生成) → Dashboard 实时呈现 → 后厨执行整改 → 效果追踪闭环。

整个系统就是 "数据采集 → 智能诊断 → 决策下发 → 执行追踪" 的完整品控闭环。
